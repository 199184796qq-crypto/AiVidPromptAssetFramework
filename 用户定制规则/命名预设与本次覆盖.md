# 命名预设与本次覆盖｜已启用

用户已确认本机制。适用于所有任务；尚未创建具体预设，不得从历史测试自动填充默认值。

## 预设范围

每套预设保存六项：画幅、整体风格、题材类型、背景音乐开关、音效开关、字幕开关。题材是都市悬疑、古装等类型，不是具体剧情。时长、人物、素材、具体光源不自动纳入这六项。

## 固定语义

- “保存为预设A，接下来都用它”：保存已确认六项并启用为活动预设，持续沿用，直到用户切换或停用。
- “这次加音乐”等单次修改：只写当前视频覆盖项，不改预设。同一视频后续改稿继续保留覆盖项。
- 开始下一条视频（包括续写新一段）时清空上一条覆盖项，恢复活动预设。若恢复的选项与续写衔接有具体冲突，说明并按需逐项确认过渡，不暗改预设、不破坏冻结衔接要求。
- “恢复预设A”：当前视频六项恢复预设A，清除对应临时覆盖；不改无关剧情和素材，不自动切换长期活动预设，除非用户明确要求持续使用。
- “以后都加音乐，更新预设A”：更新指定预设并保留旧版本；不追溯修改已交付视频。
- “切换预设B”：启用B供后续使用。当前稿是否重写按用户具体指令处理，不自行追溯。
- 用户明确停用预设时停止自动沿用，回到逐项确认流程。

## 使用与检查

每次开始一条新视频或续写新一段时，先确认新视频/续写，再主动显示当前预设及六项值，并单独询问一次：1. 沿用；2. 仅本次调整；3. 切换或管理预设。没有预设时问：1. 直接设置本次视频；2. 建立常用预设。等待用户选择后继续，不只显示就自动生成。选择沿用后不逐项重问已确定的六项。未设项仍每次只问一项。同一条视频的局部修改或重新输出不重复启动询问；用户已在本次请求中明确指定预设用法时回显确认即可。用户无需记住口令或预设名。
完整提示词仍必须展开实际设定，不得只写“沿用预设A”而省略全局定义、音乐音效或字幕约束。
恢复和临时覆盖只改变六项及必要关联内容，不更改冻结基准或通用格式，不污染其他任务。

## 存储

预设独立存于同目录下的 预设库；各套记录名称、版本和六项值，另记录当前活动预设。修改保留版本。只有六项确认齐全且用户明确启用时，才将具体预设设为活动。
当前状态：通用设计框架已启用；没有具体活动预设。用户正在设计规则，不启动第一套预设收集，不自动使用历史测试值。只有用户明确要求创建、保存或配置具体预设时，才进入参数收集。

## 框架设计与实际使用的边界

讨论、批准或修改机制，只更新通用框架，不等于授权开始一次视频任务或创建具体预设。不得因用户说“执行这个机制”就紧接着询问画幅等实例参数。
本框架是所有任务的参数管理方式：命名预设保存可复用基线，本次覆盖保存临时变化；生效值由本次明确覆盖优先于所选预设生成，未定义项仍待确认。任务结束或新建下一段时按规则清理临时覆盖；恢复、切换、更新、停用分别处理，不相互混淆。
创建具体预设必须由用户明确发起；框架讨论阶段只讨论规则，不把示例或历史测试值实例化。

## 预设与项目绑定

每个预设必须记录所属项目地址。预设仍保存在公共预设库统一管理，但选择或切换某个预设时，必须同时切换到它绑定的项目。
固定顺序：保存当前项目并读回核验 → 读取目标预设的项目地址 → 检查该项目及归档目录 → 切换项目 → 启用预设 → 恢复该项目自己的进度。
预设没有项目地址时先询问绑定项目，不擅自选择。仅查看预设列表不切换；预设列表必须显示所属项目。
