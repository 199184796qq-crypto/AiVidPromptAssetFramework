# 三层规则加载与检查

状态：R034，2026-09-20 用户批准。作为独立活动补充生效，不以本补充自动裁定历史 R031–R033 与活动指针的差异。

## 顺序与约束

每次项目创作或改稿按：框架规则 → 项目规则 → 当前段规则 → 冲突检查 → 执行 → 出稿核对。
本层级是用户框架内部的关系，不改变运行平台的系统和开发者指令优先级。
项目规则只能在框架允许范围内补充；段规则只能在项目及框架允许范围内细化。下层不得删除、放宽、覆盖上层强制要求，也不得用融合技能、临时口令或预设规避。上层明确允许配置的参数可以在下层填写，不视为冲突。
发生冲突时列出双方来源、原文条款及影响，暂停受影响操作；可调整或撤销下层要求。确需改变上层普通规则，先进入对应规则设置流程，获明确授权、保存版本并重新加载后执行；不能仅以选择下层规则直接突破上层。冻结文件仍受原保护。项目操作不得自行改写框架。

## 每层清单

框架以先读我.md及其必读文件、专项规则、活动指针和明确活动补充为入口；项目以项目根目录先读我.md及其引用为入口；段指当前实际编辑的视频片段，以该段已有目录、规则及状态记录为入口，不新建第二份视频身份。
每层维护规则索引，逐项列出文件路径、规则标识、版本、适用条件及 SHA256。索引指向正文，不复制摘要充当正文。框架记录保存在 Agent加载记录/，项目记录在项目工作记录/，段记录保存在该段已有工作记录位置；缺少段工作记录目录时可在当前段目录下建立工作记录/。
首次完整读取全部适用正文及必需引用，枚举引用直至没有未处理的必需项。必读文件缺失、读取截断或校验异常必须报告，不能标记已加载。没有额外段规则时，明确登记无额外段规则并继承上两层；不能把必需段入口缺失冒称无规则。
新项目初始化的完整读取要求仍执行；历史备份、案例及待确认方案不因读取而成为活动规则。模型分支和辅助技能依据适用条件加载，不能借此自动激活辅助技能。

## 每次执行前

核对当前项目、视频及段身份，三个层级的索引与引用清单、版本和校验值。首次接手、切换目标、入口或内容变化时重新读取受影响文件及依赖；未变化且有可核实的本 Agent 加载记录时复用读取结果，但仍执行本次变化核验。不能凭聊天记忆宣称已核验。
查询 ver/list、框架维护等没有项目或段的任务，标记其不适用，不强行创建项目；生成任务缺少目标身份时先补齐。

## 本次有效规则与出稿核对

合并为本次有效规则清单，每项保留稳定标识、上层来源、文件章节、原文或准确要求、适用理由、状态及证据。上层约束保留，下层补充逐项加入；重复要求可合并但保留所有来源。未适用项写明条件，不静默省略；同层冲突也须报告，不靠文件顺序取最后一条。
执行前强制项不允许出现未读取或未裁定冲突。出稿前逐项标记满足、不满足、待确认或不适用，并记录可核实的输出位置或检查依据；有未满足或待确认的强制项先修正或报告阻碍，不宣称完成。固定句式、格式、素材、对白、时长及独立段规则都按实际适用项核对，不使用固定数量清单代替完整核对。
按提示词优先交付规则先交付，再保存本次清单和核对记录；需要离开时按编辑锁落盘。保存输入版本、输出版本及检查时间，下一 Agent 必须核验后再复用。不得伪造已执行的检查或用户确认。

## 实现边界

这是 Agent 执行协议，记录模板见 三层规则记录模板.json。字段或文件检查只能验证记录完整性与变化，不能证明自然语言要求一定满足；需要 Agent 逐项核对。既有项目按实际接手任务补建索引，不在本次框架维护中批量修改所有项目。
