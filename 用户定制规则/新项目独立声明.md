# 新项目独立声明

状态：R035，2026-09-20 用户要求新项目开始时明文通知 Agent 与以前项目无关联，防止跨项目污染。

## 启动时必须声明

确认用户要开始新项目及实际地址后、开展任何创作前，向用户回显并在新项目根目录先读我.md开头记录以下声明，替换实际项目地址：

> 当前项目：{项目地址}。这是独立的新项目，与此前项目没有内容关联。不得沿用此前项目的人物、剧情、素材、声音绑定、镜头设计、提示词写法、临时设定、待办或审核结论。只依据框架规则、本项目规则、本段规则，以及本项目明确提供或确认的输入执行。预设仅采用本项目明确确认的字段；缺失信息不得从旧项目补齐。

每次新项目启动都执行，不因同一聊天、Agent、目录父级或模型相同而省略。先按编辑锁保存原项目，再确认新地址并读取目标项目入口；声明不改变项目入口优先读取的顺序。已存在内容的目录不得直接当空白新项目覆盖；先辨明新建还是恢复。

## 输入隔离

本次执行的活动项目、视频、段、素材映射、声音编号、草稿、待确认项与审核状态重新建立为新项目自己的记录。保留旧项目原文件，不删除历史，不声称实际清除了聊天或模型记忆。旧项目即使出现在上下文中，也不是新项目输入来源。
框架规则持续生效；共享预设必须在新项目明确确认后只取其字段，不附带原项目内容。查看历史不构成复用授权。确需建立跨项目内容关联，须用户明确指定来源、范围和用途，并按上层隔离规则处理；未明确前保持无关联，不自行推断系列关系。

## 接手与检查

新项目入口声明须被后续 Agent 读取。加载记录保存项目地址、独立声明确认状态、本次允许输入来源、预设版本、明确授权的关联项（默认空）。跨 Agent 接手先核对声明与目标身份，再按三层规则加载，不从它刚处理的其他项目恢复状态。
首次生成及每次改稿前检查内容来源是否属于当前项目。发现旧项目内容混入，移除未授权部分并依据当前输入重写；信息不足时询问，不能把旧内容作为默认值。返回已有项目时恢复该项目自己的记录，不把它误标成新项目，也不清空其已确认内容。

本次框架维护只建立机制，不启动新项目、不批量覆盖已有项目入口。新项目初始化时写入声明；已有项目接手按实际授权补充记录，不重写原规则正文。
