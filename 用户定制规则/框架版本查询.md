# 框架版本查询

状态：R018，用户在设定状态要求添加框架版本查询。

推荐指令：框架版本。查询框架版本、查看框架版本、当前框架是什么版本均走同一入口。只说版本且对象不明时澄清对象。查询无需开启设定，不触发升级、回退、发布或辅助技能启用。

## 查询步骤

从实际框架根目录读取先读我.md、用户定制规则/当前活动规则.json及规则变更日志.md，核对活动版本有对应记录，不依赖聊天记忆。显示框架名称、实际路径、本地活动规则版本、基线和启用状态、该版本主要变化。
有适用的 Agent 加载记录时另列实际加载版本；没有则写未记录，不能把磁盘版本冒称所有 Agent 已加载。规则版本、Git 提交、插件版本分别标注，不混用。发现指针与日志或文件不一致时报告异常，不自行修复或回退。

## 远端与同步状态

默认只读本地，不自动联网。可显示有可靠来源的最近已核实远端提交及规则版本，标明上次核验时间；时间缺失明确未记录，无证据写未核验，不能冒称当前远端最新版。
用户明确问远端版本、最新版本或是否与远端一致时，只读检查指定发布源和分支的提交及对应活动规则，不执行合并、覆盖、推送或激活；无法访问时报告未知。
实际框架目录与发布仓库分开时须区分二者。仓库干净不代表框架无未同步修改；判断一致须比较相关发布文件、适用插件登记及校验，不仅比较规则编号。确有差异才报告未同步改动，缺少比较依据写同步状态未核验。普通版本查询不强制完整历史或原包审计。

## 边界

查询不修改项目、预设、活动指针或历史。若离开当前编辑状态，按已有编辑锁保存必要改动；保存不等于升级。路径不明时询问框架位置，找不到不自行安装。
