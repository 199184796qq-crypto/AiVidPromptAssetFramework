本框架用于让不同的 AI Agent 按同一套规则协作完成视频创作。它把项目、视频、剧情、分镜、素材、预设、提示词、审核状态和归档记录分层管理，支持 MiniMax H3、Seedance 2、Seedance 2.5 等多个生视频工具。

## 核心能力

- 固定读取官方 H3 技能，并保护官方快照不被修改。
- 区分新视频、物理续写和逻辑延续。
- 管理全局风格、画幅、题材、光源、面光、声音、音乐、音效和字幕。
- 每个视频独立保存剧情版本；分镜只有实际生成后才记录。
- 同一项目下分别保存 H3、Seedance 2、Seedance 2.5 等工具的提示词。
- 支持编辑锁、离开状态自动落盘、历史回看、项目切换和跨智能体交接。
- 支持规则基线、增量规则列表和规则回退。

## 视频之间独立

每个视频的改稿只影响自身及对应剧情，不回写此前视频，也不传播到以后视频。新视频仅依据本次输入、已确认采用的预设字段和框架／主技能规范；不得检索、模仿或沿用其他视频成稿的写法、内容或镜头习惯。相同项目或预设不构成复用旧提示词的授权。

明确续写只继承用户授权的剧情事实或物理衔接状态，不继承旧提示词写法；查看历史也不授权复用。此为创作来源约束，不宣称能清除聊天上下文。详见 [视频内容与写法隔离](用户定制规则/视频内容与写法隔离.md)。

## H3 输出格式确认

每次生成或改稿后输出完整 H3 提示词前，单独确认本次格式：多参 Ref2VA（推荐）、纯文生 T2VA、首帧 I2VA、首尾帧 FL2VA 或尾帧 L2VA。有无素材都询问，不自动按素材决定；本次已经明确指定则回显确认。推荐不等于已选择。无素材采用多参是用户写作格式约定，不虚构上传或未定义引用，也不代表生成接口输入条件已满足。详见 [H3每次询问输出格式](用户定制规则/H3每次询问输出格式.md)。

## 启动

下载或克隆本仓库后，把实际存放目录告诉你的 Agent，并发送：

> 请先读取这个框架目录下的《先读我.md》，按入口加载适用规则，然后处理我的需求。

例如本机目录是 `E:\H3的技能`，可说“读取 E:\H3的技能\先读我.md”。其他机器不必使用同一盘符；应按实际根目录解析相对路径。Agent 需要具备读取文件的能力；仅看到 GitHub 链接不代表已经安装或加载框架。

让 Agent 先读取 `先读我.md`，然后根据任务使用：

- `Agent设定`：规划和管理框架规则。
- `新视频`：启动一个视频项目。
- `续写视频`：进入续写类型分流。
- `列出历史`：先选择当前项目或其他项目，再列出记录。
- `看剧情`、`看分镜`、`看 H3 提示词`：分别回看对应版本。

## 目录

- `h3-prompt-writing/`：官方 H3 技能冻结快照。
- `wan3-prompt-writing/`：Wan3 主技能及用户提供的 Wan3.0 视频创作者手册冻结快照。
- `用户定制规则/`：工作流、锁定、归档、协同和版本规则。
- `续写衔接冻结基准-v1/`：Motion Context 物理续写冻结基准。
- `规则版本记录/`：历史规则版本。

## 保护原则

硬规则和官方技能只能读取，不能覆盖、删除、重命名或自动升级。新规则另存为补充规则或新版本。项目内容与规则内容分开保存，提示词和剧情保持一一对应。

Windows 只读属性不能随 Git 自动传递，也不是不可绕过的权限隔离。跨机器应核验冻结文件；本框架依靠规则约束、版本记录和校验协同，不能保证任何 Agent 都绝不会改错。

## 项目怎么组织

先提供项目目录，Agent 在项目中创建工作记录和归档目录。一个项目可以包含多个视频；每个视频保存自己的剧情、素材关系、版本与审核状态。分镜实际生成后才建立记录。

| 层级 | 保存内容 |
| --- | --- |
| 项目 | 项目索引、共享资产、预设和项目状态 |
| 视频 | 独立剧情、可选分镜、素材用途及版本关系 |
| 工具分支 | H3、Seedance 2、Seedance 2.5 等各自的提示词和配置 |
| 提示词版本 | 对应剧情版本、辅助技能组合、中文/英文及审核记录 |

H3 官方提示词技能与 Wan3 本地主技能入口均随仓库提供。Wan3 基于用户提供的创作者手册，手册原样保存，本地入口不冒称官方原版 Skill。其他未提供主技能的工具仍需另行提供适配，不能直接套用 H3 格式。

## 创作、修改和回看

新视频先确认项目地址、类型及必要通用信息，生成语言丰富的本段文字故事，写清环境、事件、动作、情绪和对白。用户明确审核通过后，再选择 MiniMax H3、Seedance 2、Seedance 2.5 等模型，读取对应主 Skill 生成基础提示词；已明确的模型此时回显复用。故事审核与提示词审核独立。物理续写使用适用的重叠衔接规则；逻辑延续以新镜头开始。

预设保留画幅、风格、题材、音乐、音效、字幕等已确认设置；临时调整记录在当前视频中。选择预设会按其绑定切换项目；单纯查看不会切换。

提示词先中文审核，明确通过后才生成英文。素材上传顺序和提示词分成两个可复制文本块。必要确认与检查完成后优先交付，再保存记录；平台不支持回复后继续执行时应说明限制，不虚报保存。

修改提示词的创作内容时同步对应剧情；只改剧情不自动改提示词，而是标记待同步。历史提示词保持其原有版本关系。

| 你可以这样说 | 框架如何处理 |
| --- | --- |
| 列出历史 | 先确认当前项目或其他项目，再展示真实记录 |
| 回看2的剧情 | 查看指定历史的剧情，不自动切换 |
| 看剧情 / 看分镜 | 查看当前对应内容；无分镜时说明尚未生成 |
| 看 H3 提示词 | 查看当前视频 H3 分支 |
| 列出预设 / 显示预设 | 按上下文执行；范围含糊时再问 |
| 技能 | 项目下先选择项目技能或全局技能 |
| 开启 Agent 设定 | 进入普通规则和技能配置管理 |
| 更新框架 / 升级框架 | 同一路径：重新读取本地入口，核对规则与插件，加载并记录版本 |

这些是自然语言示例，不是必须逐字输入的口令。

## 人声与画面文字

画面文字保留原文和标点并使用英文双引号；人声编号按实际发声顺序稳定分配，对白保留原语言，旁白、跨镜、截断和听不清内容使用固定标记。详见 [画面可见文字固定格式](用户定制规则/画面可见文字固定格式.md) 与 [人声对白与画面文字](用户定制规则/人声对白与画面文字.md)。

## 指令帮助

发送 **list** 查看框架各类指令及解释；发送 **ver** 查询框架版本。大小写均可，不执行操作系统同名命令，不触发升级。完整帮助见 [框架指令查询](用户定制规则/框架指令查询.md)。

## 查询框架版本

发送 **框架版本**（或查询框架版本、查看框架版本），Agent 从本地文件核对活动规则版本、基线、主要变化，并区分实际加载记录与可核实的同步状态。默认不联网；明确询问远端或最新版本时只读核验发布源。查询不触发升级、回退或发布，无法核实的信息显示未知。详见 [框架版本查询](用户定制规则/框架版本查询.md)。

## 换机器、协作与升级

将框架和需要的项目目录一起带到新机器。只有下载框架不会带来本机项目历史或素材。其他 Agent 读取项目当前状态、提示词/剧情对应关系及技能版本后接手；已保存且无修改不重复落盘，有新修改则在切换前保存。

最简指令是：更新框架。升级框架完全同义。Agent 重新读取本地先读我.md、活动规则、变更日志及适用插件登记，核验加载并保存各自加载记录；首次加载不编造旧版本。只有本地入口确实找不到才转远程，权限或校验错误不属于找不到。本地加载不代表 GitHub 最新版。明确远程更新框架或远程升级框架才直接检查远程，并按备份、冲突与冻结校验流程应用。首次接手需提供安装目录并读取入口；发布不会自动传播到其他 Agent。

规则修改需用户开启 Agent 设定，发布需同步授权。回退只能使用实际存在的历史副本；早期基线文件尚未包含完整可恢复快照，不能保证任意历史时间点都可恢复。R002 起保留了各次变更前副本，可结合 Git 历史核对。

## 说明

这是工作流与资产管理框架，不包含具体视频生成服务。各生成工具的提示词必须遵守对应工具的官方格式。

## 项目资产管理（R023）

按用户指定项目建立“角色资产/人物资产”“角色资产/公共资产”“角色资产/场景资产”三类入口。具体人物目录保持扁平，人物图、服装、专属道具、声线和相关记录同层保存；场景原件集中保存，人物可通过软链接或快捷方式关联。上传时使用真实媒体路径，不使用快捷方式代替素材。

支持“创建角色资产目录”“查看资产”“整理资产”“关联场景”。这些是Agent执行规范，不是独立后台程序；不会自动重整其他项目，也不继承参考项目的剧情和素材。详见[项目资产管理](用户定制规则/项目资产管理.md)。

## Wan3 并列主技能与冻结保护（R024）

目标模型为Wan3时，从[wan3-prompt-writing/SKILL.md](wan3-prompt-writing/SKILL.md)进入，按素材选择全能参考或首尾帧等模式。该主技能与H3并列，不属于辅助技能。

用户提供的[Wan3.0视频创作者手册](wan3-prompt-writing/references/Wan3.0视频创作者手册.md)保持原始字节；SKILL.md是本地编写的框架入口。整个技能目录及[冻结保护补充](用户定制规则/Wan3主技能冻结保护.md)与H3享有同级用户框架保护：禁止修改、覆盖、删除和自动升级，后续适配另存版本，保留v1原件。

调用前核验SHA256。来源记录中的原电脑绝对路径仅用于追溯；跨机器以实际框架根目录解析相对路径，并将保护清单中的原根目录映射到当前根目录。Windows只读属性不随Git传播，不等于不可绕过的系统权限锁。

## 项目级规则入口（R025）

设置项目目录后，优先读取项目根目录的 先读我.md 及其引用规则。项目级更新仅重新加载指定项目的本地规则并分别记录，不修改框架或联网；项目规则、项目加载记录和项目快照不纳入框架远端发布。


## 项目规则冲突裁定（R026）

项目规则不得静默覆盖或对冲全局规则。发现冲突时暂停受影响操作，明确列出差异，等待用户选择；用户未选择前不执行冲突部分。项目规则不能解除冻结基准。


## 模型资产占位符（R027）

提示词生成前只使用文案中的人物和场景名称。进入提示词阶段后，先输出素材上传块，再输出提示词文字块；SD/Wan3使用 @图N，H3使用 <Picture N>。磁盘路径仅在用户明确提供时追加。


## 项目初始化（R028）

确认项目目录后，输入“项目初始化”即可按框架规则创建项目骨架、入口和索引。缺失才创建，保留已有内容；不生成具体资产、剧情或提示词，项目规则不纳入框架发布。
