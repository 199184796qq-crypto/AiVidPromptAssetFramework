# 辅助技能扩展机制

状态：用户确认，R010（补充 R006、R007）。适用于全部工具、项目及 Agent。

## 安装引导与统一位置

用户提出安装技能时，主动引导其提供该功能 Skill 的地址或文件；已提供则直接读取，不重复索要。只给名称且无法确定来源时先询问，不猜测安装对象。文件可为完整技能目录、压缩包或 SKILL.md；必需引用缺失时说明缺项并引导补齐，不把不完整包标记为安装成功。
完整读取技能及必需引用，说明用途、依赖和适用功能，按下方安装流程执行。这里的“学会”指本次读取理解并将文件保存以供以后加载，不声称模型获得永久记忆。
所有辅助技能，包括功能下属技能，统一安装到框架根目录的 辅助技能/packages/{id}/{version}/。原机器根目录为 E:\H3的技能；换机器按实际根目录解析。项目仅保存选择、版本与使用关系，不把项目目录作为唯一安装位置。
安装完成后展示名称、版本、全局安装位置、适用范围和核验结果，明确是否已为当前任务启用。安装仍遵守 Agent 设定开启要求。

## 项目中的“技能”入口

用户在项目下仅输入“技能”，范围不明确时，先提供“当前项目技能”与“全局技能”供选择，一次只询问一项。明确说“当前项目技能”“全局技能”“查看某技能”等则直接执行对应意图。
当前项目技能来自该项目实际选择或使用记录，列出名称、版本、适用功能、关联视频或提示词、当前启用情况。全局技能来自真实登记及安装文件，列出名称、版本、用途、适用范围及可用状态；已登记但缺失文件的项标为不可用，不计为已安装。
列表提供本轮序号供选择，查看不等于启用。用户选择后，若尚不清楚是查看详情还是应用、应用于哪个功能或提示词，先澄清；已明确则执行，不重复问。没有技能时如实说明并提供安装入口，不自动安装示例技能。

## 安装记录与回溯

每次安装或升级在 辅助技能/安装记录/{id}/ 保存独立记录，包含时间、来源、固定版本或提交、文件清单及 SHA256、依赖核验、适用范围、前一版本、操作结果。升级保留旧版本，失败保留记录并标为失败。
支持查看技能详情、来源、历史版本、安装记录及项目使用记录。回看旧版不切换当前版本；用户明确要求回退时，按 Agent 设定与版本规则调整指定范围，保留其他项目原有绑定，不重写旧提示词。

## 范围与登记

辅助技能提供专业引导和内容优化，最终由目标工具主技能生成正式提示词。全局技能可供全部功能选择；功能下属技能通过 parent_function 标明 H3、Seedance 或具体功能，仅在兼容范围内使用。全局可用不表示全局自动启用。
维护 辅助技能/技能登记表.json；登记稳定 id、名称、版本、来源及固定提交、入口相对路径、SHA256、作用域、所属功能、依赖、兼容工具、分发许可和安装状态。同名不同版本不可静默替换。
框架登记不等于宿主原生安装；宿主不支持原生技能发现时，通过框架入口显式读取 SKILL.md。不得声称无法访问的技能已安装或已加载。

## 安装与配置

安装、升级、停用或修改公共技能配置须处于用户开启的 Agent 设定状态，并有具体技能来源及用户要求。未指定技能只建立扩展机制，不把举例当安装任务。
读取完整 SKILL.md 及必需引用，核对依赖、适用范围、分发许可和与硬规则的冲突。安装到独立版本目录 辅助技能/packages/{id}/{version}/，不改官方冻结技能。依赖未满足或冲突未解决时标为不可用并说明，不能强行启用。
新增登记项保留修改前记录，成功后核验入口及文件校验。升级另存版本；停用不删除被历史提示词引用的版本。运行脚本或外部操作仍遵守用户授权范围。

## 每条提示词的选择

创作时可查看兼容的已安装技能，由用户指定本条使用的技能组合；明确选择直接执行，含糊时逐项询问。安装不自动启用，其他提示词的组合不自动继承，已确认的复用选择可以沿用。
辅助技能启用后，必须执行下方完整流程，不能只抽取零散建议。主技能负责最终模型格式，但不能以此为理由不向用户展示辅助技能的冲突要求。辅助技能不能改变硬规则。

## 辅助技能自身流程强制执行

1. 先完整读取所选版本的 SKILL.md 和必需引用，将其适用于本次任务的规定流程、强制要求、必需输入、确认点和输出要求逐项列给用户。标明文件或章节来源，区分原文要求与 Agent 的解释；不得虚构技能规定。
2. 按技能规定的顺序逐项执行，并让用户知道当前步骤及完成情况。需要用户参与的步骤一次只问一项；用户已经明确的信息回显复用，但不能跳过该步骤的实际核对。条件分支不适用时说明原因，不把选择性步骤冒充强制，也不擅自省略适用的强制步骤。
3. 如技能要求与框架规则、用户已确认设定、上一步结果或其他技能冲突，列明双方要求、来源、具体影响和可行处理方式，让用户判断。用户裁定前不执行依赖该裁定的工作，不静默删除或覆盖。冻结硬规则原件不修改；只能在允许范围内适配或停用冲突部分。既有用户裁定在相同适用范围内回显复用，不重复索取，但安装记录中的一般性“以框架为准”不能替代未经用户作出的具体裁定。
4. 将执行后有效且完成必要确认的结果融合到上一步已有结果中，保留不受影响的事实与内容，不能只交付孤立建议或用技能模板整体替换原稿。保存上一步版本与新版本的关联，记录新增、调整及未采用内容和原因。影响已确认剧情或对白时按故事审核规则重新确认；更新提示词时同步对应剧情并标记其他受影响分支。
5. 交付前核对各项适用要求已执行或有明确用户裁定；依赖缺失、步骤未完成或冲突未解决时如实标记，不声称完整执行。准备完成后按提示词优先交付规则展示，随后保存技能版本、流程清单、步骤状态、用户裁定和融合记录，供其他 Agent 接手回看。

## 记录与回看

展示后在该视频对应工具提示词版本目录保存辅助技能使用记录，采用 辅助技能/提示词技能记录模板.json；记录实际版本、顺序、配置、用户确认结果及对剧情/分镜的影响，关联具体提示词与剧情版本。未用技能时记录空组合，不虚构调用。
支持自然语言“列出辅助技能”“本条用了什么技能”“看技能配置”。查看不安装或启用。修改组合只影响指定提示词的新版本；旧版提示词及使用记录保留。

## 同步与恢复

公共登记表、规则及允许分发的版本文件可随已授权框架发布同步；无分发许可时仅记录来源与固定版本，不上传包内容。项目归档保存实际使用记录和允许保存的依赖快照，不上传私有项目数据作为公共框架内容。
接手 Agent 按使用记录核验本地安装、版本和依赖；缺失时明确提示并按安装授权处理，不自动换成最新版或相似技能。遵守框架升级与同步规则，不宣称其他机器已自动安装成功。

## 当前实现边界

本机制是 Agent 可执行的文件协议与登记模板，具体安装由具备文件访问能力的 Agent 执行；不包含自动安装服务或后台同步进程。
