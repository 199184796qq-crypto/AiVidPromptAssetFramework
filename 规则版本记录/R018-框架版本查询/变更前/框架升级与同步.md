# 框架升级与同步

状态：用户已确认，R012（补充 R003、R005、R011）。适用于所有机器及 Agent。框架发布源为 https://github.com/199184796qq-crypto/AiVidPromptAssetFramework 。

## 更新与升级统一入口（R012）

推荐最短且对象明确的指令：**更新框架**。**升级框架**与它完全同义，执行相同路径，不再询问更新还是升级、也不再要求选择本地优先。

“本地更新”“本地升级”“更新框架指令”保留为同义入口。在当前对话明确操作本框架时，单独的“更新”与“升级”也走同一路径；上下文不能确定对象时，只询问要更新哪个对象，不擅自更新软件、模型、项目或其他技能。“远程更新框架”与“远程升级框架”同义，明确进入远程分支；“同步远端”仍是发布操作，不混同获取更新。

统一执行顺序：

1. 确定已安装框架的实际根目录。原机器为 E:\H3的技能；其他机器使用已记录的安装路径。存在多个且无法确定当前框架时询问路径，不擅自选取。
2. 按编辑锁保存有新改动的项目状态；无新改动不重复保存。重新从磁盘读取根目录的先读我.md，不使用聊天记忆或此前缓存替代。
3. 按入口重新读取防漂移规则、硬规则保护要求、当前活动规则.json、规则变更日志.md及适用专项规则。核对辅助技能登记表、相关安装记录、版本与文件校验，识别规则升级和独立插件升级；不能仅凭规则编号判断没有更新。
4. 与本 Agent 上次加载记录比较。无记录时建立首次加载基线，不编造此前版本或变更。读取所有适用新增或修改内容，校验入口引用和依赖；沿用已明确的用户冲突裁定。遇到未裁定冲突或校验异常，保留原状态并报告，不宣称升级完成。
5. 核验成功后加载本地有效版本，并保存本 Agent 的加载记录：实际根目录、时间、活动规则版本、适用规则与插件版本及校验值、前次版本（如有）、变更摘要和未完成事项。记录放在框架根目录的 Agent加载记录/ 下，以当前宿主和 Agent 可识别标识区分；不得覆盖其他 Agent 的记录。简短报告已加载版本、主要变化及未完成事项。

本地入口存在时，此命令完成本地框架重新读取和加载，不自动检查远程，不声称已获取 GitHub 最新版。只有确认本地入口不存在、找不到时才访问已指定远程源，按下节获取新版。权限错误、读取失败或校验异常不属于找不到。

明确远程更新时按下节获取新版，随后仍执行以上重新读取、核验和加载记录步骤。更新已发布或本地已确认规则不需要另开 Agent 设定；自行修改规则仍须用户开启设定。

## 获取新版

本节仅在用户选择远程升级，或本地优先且确认找不到本地入口时执行。读取当前安装路径、版本与远程状态。该请求授权获取已发布版本，不授权自行设计新规则，不需要为单纯获取新版另开 Agent 设定。
先按编辑锁保存未保存的项目进度；无新改动不重复保存。备份当前框架及活动指针，获取目标版本并比较变更、规则清单与硬规则校验。不得把仓库新内容未经核验直接覆盖到正在使用的技能目录。
本地有修改时保留副本；冲突保留双方并报告，不强制覆盖。硬规则有差异、校验失败或目标版本资料缺失时，停止激活并报告，保留原版本；不得解除只读保护或自动升级冻结内容。
验证通过后应用普通规则更新，记录安装版本、来源提交、路径映射和校验结果，重新读取先读我、当前活动规则及适用专项规则，然后继续工作。不把下载成功当作已加载成功。

## 修改并发布

只有用户明确开启 Agent 设定后才可设计和修改普通规则。先保存旧版，登记变更、来源版本及用户确认依据，再验证入口引用、版本记录及冻结文件未变。发布到 GitHub 必须有用户的同步或发布授权。
推送前核对远程是否有其他 Agent 的更新；不得强推覆盖。存在冲突时保留版本并请求用户裁定。推送成功后核验远程提交，报告版本；失败时准确区分本地已保存和远程未同步。

## 项目与交接

升级不自动改写项目剧情、分镜、提示词或历史归档。项目保留原规则快照；采用新版进行创作时记录新工作版本的规则依据。
其他 Agent 只有能访问发布源、完成更新并重新读取后才算使用新版，不能声称所有 Agent 已自动同步。交接记录标明实际加载的版本与尚未处理的兼容事项。
